## 2. 必改清单（P0，迁移执行时照此操作）

### 2.1 `package.json` 依赖重组

- **删**：（两线中不存在的死包；peer + dev 全删，源码引用同步清零）；
- **增（仅 devDependencies，钉新线）**：（新线才有、且本插件只 `import type` 的包
  ——编译期擦除、运行时缺席无害，不进 peer、不进 `dsh.client.inject`）；
- **peer 改并集**：其余两线都存在的 `@deepseek-ai/dsh-*` peer 从 `^旧线` 改为
  `^旧线 || ^新线`（⚠️ 语义与预发布规则见兼容手册 §1.2）；
- **dev 钉死新线**（⚠️ dev 写并集是实测坑：pnpm 沿用 lockfile 首臂旧解析）；
- `dsh.client.inject`：只列**所有支持线都存在**的包（⚠️ 新线专属包进 inject 会让
  旧线 web 启动硬失败，见手册 §1.3）；
- tsdown `neverBundle`：对齐两线 `PLATFORM_MODULES` 交集（手册 §1.4）。

### 2.2 源码迁移

**import type 迁移表**（逐条：文件:行 | 旧导入点 → 新导入点；新包只 type-only）：

```ts
// 文件:行
- import type { X } from '@deepseek-ai/dsh-旧家'
+ import type { X } from '@deepseek-ai/dsh-新家'
```

**运行时特征探测**（每处：两线证据 文件:行 + 探测代码；写法规矩见手册 §3.3）：

```ts
interface Accessor {
  新API?: () => T    // 新线（正向探测）
  旧API?: T          // 旧线（兜底）
}
const value = obj?.新API?.() ?? obj?.旧API ?? fallback
```

### 2.3 验证

`pnpm install` → `pnpm run typecheck` → `pnpm run build` 全绿 = 编译级迁移完成。

## 6. 迁移后需实测的运行时点

1. 软禁用链路：临时压低 MAX 触发一次，确认「已停用」面板照常渲染、index-inject 无残留；
2. 装载链路：`dsh plugin add` → profile 装载一次通过（新线新增的安装机制走一遍）；
3. 端到端：设置面板 + 全部业务工具/端点 + HMR 热替换；
4. **旧线冒烟**（双线坐实）：装载 + 面板 + 工具端到端，必须覆盖每个特征探测
   fallback 分支；冒烟不过 → 回到「MIN 同步上调」方案。
